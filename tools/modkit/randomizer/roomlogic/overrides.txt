# Hand-made changes to the Randomizer's logic. solve.py (and rndgen.py, which runs it) applies them on top of the rooms'
# logic (rooms\<room>.txt: the room logic's simulation of each room) and the connections (connections.txt); they stay
# when roomlogic.py makes those again. A change here flows on: everything past it is worked out again (python solve.py:
# a few seconds; README.txt says more).
#
# A line adds a way or a requirement to the simulation's; only a drop line takes one of its ways away, saying why.
# Lines (# starts a comment):
#   add <room> from <x,y> to <way out or place> : <requirements>
#       another way there (sufficient), as well as the simulation's. "from *": from every way in; "to *": to every way
#       out, place and spot. A way out is "out <id>" as the room's file names it (left in the state the player came in
#       in); a place is "loc <type> <number>" or its name ("loc skill point 59"); a spot is "spot <tag>". In place of the
#       room, "area <number>" (from * to *): every room of the area.
#   require <room> from <x,y> to <way out or place> : <requirements>
#       every way there, the simulation's and the add lines', needs this as well (necessary).
#   require <room> out <id> : <requirements>
#       going through that exit needs this as well, on top of getting to it, wherever Entrance Rando has it lead.
#   drop <room> from <x,y> to <way out or place> because <why>
#       the ways there so far (the simulation's, and the lines' before it) aren't there: the add lines after it give
#       the ones that are (none: no way there).
#   drop <room> from <x,y> to <way out or place> : <requirements> because <why>
#       the add lines there leave these out, where every one of the simulation's ways takes them: a weapon ("attack"),
#       a key ("key N"), a Program Chip ("chip N") or an event ("event NAME"). The build stops at an add line that
#       leaves one out with no drop line saying why: a hatch's, a barrier's, a locked door's or a switch's requirement
#       isn't taken away unseen.
#   link <room> out <id> -> <room> in <x,y>
#       that exit leads somewhere else.
#   only <room> : <items>
#       the room takes the player's other abilities and sets away: a way through it that needs one isn't there.
#   outoflogic <room> loc <place> : <why>
#       that place out of logic, from every way in (as a place the logic doesn't reach: it never holds an ability or a
#       key); the Check Tracker says why beside it ("Water level based").
# The add and drop lines apply in the file's order; then the only lines, the require lines and the outoflogic lines.
#
# Requirements: alternatives separated by |, any one of which is enough; each a list (spaces or commas) of: djump,
# adash, gdash, hijump N, mario, link N, belmont N, megaman N, samus N, gamej N, gamec N (that many of the item), varia
# (the Varia Suit), cursed N (that many of the three cursed equipment pieces), air N (that many of the 10 Air Upgrades
# got to: the logic counts the ones at places it gets to, as the items are placed), key N (the key of the locked door whose
# objectNum is N: doors.csv), chip N (Program Chip N: the new game's option Chip Randomizer; with it off the player has
# all six), attack (any ability set's attack), event NAME (events.txt), option NAME (only with that option on), pct N
# (N% of all the checks in logic: bosses.txt's shares, which the room logic's reach counts), nothing, or never.
#
# Say why next to a change (a comment), so whoever reads it later knows. Examples (not in effect: they're comments):
#   add rMain_62 from * to loc skill point 59 : hijump 2
#   require rMain_62 from 48,1920 to out 0,224 : megaman 2
#   require rMain_62 out 880,96 : megaman 4
#   drop rMain_18 from 56,240 to out 1992,224 because <what the playtest found>
#   add rLink2_PalaceW_7 from 48,480 [water 3] to out 1392,272 : nothing
#       (a way in with a carried state after it: coming in in that state only)
